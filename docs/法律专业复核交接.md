# 法律专业复核交接

当前 `rules/approved/` 中没有真实通过的规则，全部场景保持关闭。模型自评、另一个模型评价、程序结构测试和网页安全扫描均不能替代法律专业人员对规则的审核。

在项目本地已抓取并建立索引后，可运行 `python3 scripts/search_sources.py --term 押金 --source housing_lease` 或用 `--article 10` 指定条号。检索会先核对快照与索引哈希，再返回条文定位和来源网址；民法典结果现带有编、分编、章、节及附则定位，两份官方全文逐条层级对照一致；命中、未命中都不能替代全篇核对或适用判断。公开 Git 仓库不含本地全文，单独下载源码须先按 README 抓取与建索引。

`rules/candidates/` 中的 JSON 是本地 Qwen 草稿，`raw_content` 保留模型原始输出，`card` 只把格式正确的条号统一成数字并绑定所给原文的哈希。每卡 `dialogue` 预期含三轮 `user` / `assistant`，要逐轮复核事实补充、更正前提后答复是否随之改变。机器结构检查及“两个网页逐条一致”都不是法律准确性结论。候选包仅供逐项审核，不应直接发布为法律问答。

此私人候选包另含 `sources/normalized/` 中的本地法条文本，供复核人员逐条比较条文、上下文与遗漏的司法解释。分条解析最近从三份司法解释的 16 条正文中剔除误并入的分节标题，受影响索引哈希及来源清单已变更；六份补充候选均标记清单变更，须复核其实际影响。这些文本不进入公开源码或 SkillHub 安装包；复核时仍须回到来源台账所列正式发布页面确认现行版本和效力。

押金场景的 `rules/candidates/supplements/rent_deposit.json` 是本地 Qwen 的第三版未审候选；条文和提示词绑定、四条必引引用及三轮逐字更正通过机器结构检查。但人工阅读发现它把“无正当理由不得扣减”倒置为“扣减仍须无正当理由”，`known_error_screen_pass: false`。旧版备份也有漏列引用、保障房一概排除等错误。请先读 `rules/candidates/supplements/rent_deposit.REVIEW.md`，不得把当前稿或旧稿合并到已审规则。

无借条转账场景也有 `rules/candidates/supplements/loan_no_note.json`：加入民间借贷规定第 2、14、16 条及时间效力规定第 1 条后，本地 Qwen 的首次 JSON 截断被拒，第二次输出的来源和哈希绑定通过。其举证规则表达扩大了条文的诉讼前提，三轮示例的债务方向与前提更正仍有缺陷；新增更正信号检查后 `structure_pass: false`。详见 `rules/candidates/supplements/loan_no_note.REVIEW.md`；它同样未获专业复核。

借款到期未还场景新增 `rules/candidates/supplements/loan_overdue.json`，输入民法典第 188、195、675、676 条、民间借贷规定第 28、29 条及时间效力规定第 1 条。旧稿第三轮只新增展期事实，却因出现“更正”二字通过旧结构检查，现存于私人 `versions/`。更新后的生成器要求第三轮逐字撤回前两轮用户原话；当前重生稿通过该绑定，但仍把逾期利息条件与 LPR 上限过度概括，把展期证据不足说成可直接按原到期日判断。详见 `rules/candidates/supplements/loan_overdue.REVIEW.md`，应退回而非因 `structure_pass: true` 签核。

租房维修场景新增 `rules/candidates/supplements/rent_repair.json`，输入民法典第 704、712、713 条和《住房租赁条例》第 2、35、49、50 条。第一稿与第二稿均为未审 Qwen 输出，第一稿存于 `versions/`。第二稿曾通过仅看“更正”字样的旧结构检查；新检查要求逐字撤回前两轮用户原话，因此当前 `structure_pass: false`。人工阅读还发现自行维修费用被泛化为“索赔”、民法典与条例的时间及土地前提混写、集体土地答复过于绝对等问题。请先读 `rent_repair.REVIEW.md`。

提前退租场景新增 `rules/candidates/supplements/rent_early_end.json`，输入民法典第 510、562、563、565、566、577、730 条、合同编通则解释第 52、53、61 条和时间效力规定第 1 条。首次保存稿未输入第 510 条，后续一次 Qwen 重生虽输入却漏列第 563 条引用，被程序拒收并保留原文；当前稿的原文哈希、必引条号及第三轮逐字撤回通过机器检查。人工阅读发现它省略了不定期租赁的合理期限前通知要求，第二轮在租期未定时跳到“定期合同”分支，还错误概括旧稿。详见 `rent_early_end.REVIEW.md`。当前六份补充候选中，借款到期未还、提前退租和押金三份通过字面结构检查，另外三份未通过；押金稿另有已知硬性法律错误，六份都不能代替法律专业审核。

同包的 `rules/candidates/REVIEW_WORKSHEET.md` 按十二场景列出候选解释、条件、例外、引用条文与连续三轮问答，并留有来源效力、适用范围、修订意见和签核字段。它由程序排版，初始状态始终是“未签核”；填写工作表不能代替独立的正式审核记录。

同包新增 `tests/LEGAL_ACCEPTANCE_WORKSHEET.md`，按开发集 60 组和最终保留集 20 组列出原始测试输入及空白审核字段。专业人员须独立写出法律预期、来源版本、不可出现的断言和实际结论；最终保留集的预期与依据不可交给生成候选的 Qwen 或公开技能包。六组故障题另需真实故障注入日志。此表未填、未签核，不能算作 80 组验收通过。

复核人员应按每条候选规则及其三轮示例逐项确认：引用的正式文件和现行效力；公布与施行时间；涉及 2021 年前事实时的时间效力；条文、款项、例外和司法解释是否完整；普通话术是否改变法律含义；哪些事实缺失时只能追问；哪些结论不能推出。记录具体审核范围、身份类型或专业资质、日期、意见、退回原因。来源变化后重新审核受影响规则。

十二张原始候选均只输入了少量民法典条文。请先按 `plan/SOURCE_COVERAGE.md` 排查可能影响各场景的配套资料，再决定哪些原稿需要重生成或退回；该矩阵本身不认定资料对个案适用。

资料预核已按 `SOURCE_MANIFEST.json` 的 15 个来源编号列出各官方页面能直接核实的公布、施行或版本线索，见 `reports/EFFECT_PRECHECK.md`。重点包括：民间借贷对照页在 2026 年发布的是标为 2020 年第二次修正的正文；2025 年《住房租赁条例》第二条限定城镇国有土地上的住房租赁，第四十九条涉及集体土地另行安排；2025 年《婚姻登记条例》有 5 月 10 日施行边界；民法典时间效力规定第 20、25 条还涉及特定跨 2021 年合同事实。复核相关候选时，要把文本版本、事件时间和土地情形写入实际适用范围，不能仅凭页面日期或问题类别放行。预核表不改变“待逐项核验”的状态。

离婚登记流程另补入 2025 年修订《婚姻登记条例》：国务院令第 804 号的生态环境部转载与司法部国家行政法规库各提取 28 条，自动对照在括号字形归一后零差异，记录见 `reports/MARRIAGE_REGISTRATION_CROSSCHECK.json`。请结合民法典第 1076–1078 条，核查协议签署、登记机关收到申请、领取离婚证是否被候选混为同一时间节点；若事实跨越 2025 年 5 月 10 日施行日，须核对相应历史版本。该新增资料及机器比对尚未经过法律专业适用审定。

基于上述资料的 `rules/candidates/supplements/divorce_agreement_registration.json` 仍是未审模型稿。首次输出因漏列必引条文被拒；第二次虽保存，新增的对话引文检查发现它提到条例第 14 条却未列入引用清单，`structure_pass: false`。其第三轮还仅凭“2024 年签协议”便断言 2025 年条例不适用，不能据此判断后续登记流程版本。请先读同目录 `.REVIEW.md`，把它作为退回修改的问题清单，不直接签核或对外使用。押金补充旧稿曾漏列民法典第 733 条；当前重生稿补齐所需引用，但出现更严重的否定条件倒置，已单独退回。

新增登记条例后，来源清单的整体哈希已变化。两份此前生成的补充候选在 `reports/SUPPLEMENT_AUDIT.json` 标记 `source_manifest_changed_after_generation: true`；程序重新核对各自输入条文和提示词绑定通过，但复核人员仍须检查新增或变更来源会否影响原场景。原候选及模型原文保持原样，未伪造为按新清单重新生成。

工程上，仅在复核真实完成后创建 `rules/approved/<rule-id>.json` 与 `review/<rule-id>.json`。规则至少包含 `id`、`status: approved`、`scenario`、已审核的固定 `approved_text`、`conditions`、`exceptions`、`required_facts`、`unsupported_conclusions`、`time_boundary`、`region`、`references`，以及机器可检查的 `applicability`（`event_date_from`、`event_date_through`、`regions`）和非空 `fact_pattern`。`fact_pattern` 的键须列入 `required_facts`，取值为审核过的具体事实值；任何新增或更正事实未匹配时，程序不会显示这条规则的固定文本。日期范围需要按照法律事实的实际时间锚点审核，不能直接填发布日或今天。引用记录必须含来源 ID、条号或定位、原文片段；民法典引用还需对应规范化条文哈希。

审核记录须写入 `decision: approved`、`reviewer`、`reviewer_role`、`scope`、`review_date`，以及审核时规则文件的 `rule_sha256` 和来源台账的 `source_manifest_sha256`。程序校验这些字段与当前文件能否对应，**不验证审核者真实资质，也不证明其法律判断正确**。不得为了让程序通过而填写虚构的审核者或“已核验有效”状态。

完成复核后，重新跑来源比对、程序故障注入、法律与事实验收、多轮对话和普通读者理解测试；只有实际通过的场景可列为对外开放。
